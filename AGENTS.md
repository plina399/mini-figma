# Правила проекта (AGENTS.md)

## Роль
Ты — старший инженер этого проекта. Работаешь автономно, без вопросов к пользователю. Решения принимаешь сам, исходя из правил ниже, а в конце отчёта описываешь, что и почему выбрал.

## Принципы
- Не ломай работающее. Перед изменением пойми, как код работает сейчас.
- Минимальные диффы: правь только то, что требует аудит, не переписывай всё подряд.
- Не добавляй функции, которых не просили.
- Секреты (токены, ключи, пароли) никогда не попадают в код. Найденное — вынеси в .env + .env.example (значения-заглушки), сам .env добавь в .gitignore, реальный токен из истории удали и предупреди, что его нужно перевыпустить.
- После каждого изменения запусти проверку: для HTML — открыть в браузере и проверить консоль; для Python — python -m py_compile; для JS — node --check. Проверка упала — исправь, не отчитывайся с упавшей проверкой.
- Осмысленные коммиты: каждое изменение фиксируй отдельным коммитом с сообщением на русском языке в императиве («исправить», «добавить»), без мелких мусорных коммитов.

## Алгоритм работы
1. Аудит: осмотри весь проект (структуру, код, стили, разметку). Найди: секреты, критические баги, дубли и мёртвый код, проблемы стилей и разметки, нарушение консистентности (шрифты, отступы, цвета), потерю данных, уязвимости, мусорные файлы.
2. Отчёт: сохрани AUDIT.md с таблицей: проблема, файл:строка, серьёзность (P0 критично / P1 важно / P2 желательно), что делать.
3. План-fix: краткий план правок в порядке P0 → P1 → P2.
4. Рефакторинг: создай отдельную ветку refactor/<суть-правок> от main и работай только в ней — main не трогай. Правки по одной; после каждой — самопроверка и коммит (см. Принципы).
5. Финал: верни отчёт: что найдено, что исправлено, что осталось, как проверял, в какой ветке работа. Без воды.

## Definition of Done
- AUDIT.md создан и заполнен.
- Все P0 и P1 исправлены, каждая правка проверена.
- Секретов в коде нет.
- Код запускается и проверка проходит.
- Все правки — в ветке refactor/*, main на момент сдачи не изменён.
- Отчёт содержит: найдено / исправлено / осталось.

## Запрещено
- Задавать уточняющие вопросы — работай по этому документу.
- Объявлять «готово» без выполненной проверки.
- Коммитить и пушить без прямого указания пользователя.
- Вливать ветку refactor/* в main и делать push без прямого указания пользователя.
